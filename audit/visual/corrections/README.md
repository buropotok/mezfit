# Mezfit — единый реестр предлагаемых исправлений

**Статус:** редакторские предложения, не утверждённые изменения. Ни одна строка автоматически не применяется к каталогу.

## Файлы

- `proposed_corrections.jsonl` — 663 записи; одна запись на упражнение со статусом не `clean`. Точные значения из исходника находятся в `current_values_exact`, а оригинальные требования аудита в `issues` и `proposed_corrections_as_audited`.
- `proposed_corrections.csv` — 663 строки для фильтрации и согласования; длинные исходные инструкции не дублируются в CSV (они полностью доступны в JSONL).
- `audit_quality_flags.csv` — 261 флагов для 204 уникальных ID; замечания по качеству аудиторских метаданных, **не** самостоятельные новые ошибки упражнения.

- `clean_with_priority`: 60 упражнений объявлены чистыми, но имеют P1/P2. Они **не включены** в 663 предложенных исправления и не переводятся в проблемные автоматически.
- `issue_with_none_priority`: 1 проблемная запись без приоритета. Приоритет подлежит экспертному решению.
- `evidence_original_gif_missing`: 200 старых записей без отдельного `evidence.original_gif`. В исходных данных есть `gif_url`, поэтому ссылки на оригинал могут быть построены. Отсутствие этого отдельного поля **не доказывает**, что GIF не был просмотрен.

## Схема JSONL

- `id`, `name_ru`, `name_en`, `gif_url`: значения непосредственно из исходного этапного каталога, без исправлений.
- `audit_status`, `audit_priority`, `confidence`: **как в завершённом аудите**, без подмены или автокоррекции.
- `affected_field_paths`: поля, затронутые исходными замечаниями, в том числе вложенные `instructions.ru`, `muscles.primary` и др.
- `current_values_exact`: буквальные действующие значения исходных полей (строки, массивы, структуры).
- `issues[]`: исходные предложения и доказательства для каждого замечания, с разбиением полей.
- `review_state=pending_editorial_review`, `approval_state=not_approved`, `exact_field_replacements=null`, `auto_apply_allowed=false`: новые значения полей ещё должны быть написаны и утверждены.
- `provenance`: SHA-256 исходного каталога и этапа, пути результатов, blob SHA накопленного аудита.

## Как использовать

1. Сначала разобрать флаги с приоритетом `blocker`, затем 60 неоднозначных `clean` и один `none`-приоритет. Не изобретать проблемы для чистых упражнений.
2. Для подтверждённых P0/P1 подготовить **точный replacement JSON** на основе оригинальных GIF и текущих значений. Тексты `proposed_correction_text` — инструкции редактору, **не готовые JSON-патчи**.
3. Для вероятных расхождений нужна повторная проверка. Для названий — проверка вариантов RU/EN. Дубликаты сравнивать без автоматического удаления.
4. Если затронута анатомия, использовать полную исходную таксономию 69 ID и авторитетные источники. Не выводить активность мышц только из GIF.
5. Проводить правки в актуальном каноническом каталоге через отдельные PR по `AGENTS.md`; для правок уже опубликованного каталога — отдельная защищённая публикация через разрешённый workflow Dexie Cloud с exact ID/field allowlist, предварительным diff, backup и readback.
