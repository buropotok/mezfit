# Gym Keeper exercise catalogue parity

Status: implemented reference parity for Mezfit `Упражнения` across category navigation, Russian names, category artwork and bundled exercise media.

## Evidence priority

For this module the supplied Gym Keeper APK and product-owner screenshots are the primary functional/UI/UX reference. Static DEX/resource evidence is useful for discovering capabilities, but **a list of discovered features is not a substitute for reproducing the observed interaction sequence and information architecture**.

## Screenshot-confirmed catalogue flow

The verified Gym Keeper flow is:

1. `Упражнения` opens the **category list first**, not a flat exercise catalogue.
2. Primary categories are `Грудь`, `Руки`, `Спина`, `Ноги`, `Плечи`, `Корпус`, `Фулбоди`, `Кардио`, `Другое`.
3. Selecting a category opens that category's exercise list. The header uses Back + category name + Add + Search.
4. Directly under the header is a compact badge/chip filter row. The favourite filter is a star. Category-specific subgroup chips precede equipment chips where the reference exposes them. Screenshot-confirmed examples:
   - Грудь: `Середина`, `Верх`, `Низ` + `Свой вес`, `Штанга`, `Гантель x1`, `Гантели x2`, `Трос`, `Тренажер`, `Другое`;
   - Руки: `Бицепс`, `Трицепс`, `Предплечье` + equipment chips.
5. Exercise rows are compact cards with an exercise media thumbnail, title and overflow action.
6. The overflow menu is the primary catalogue action gateway and exposes `Информация`, favourite add/remove, `Дублировать`, `Редактировать` as applicable.
7. `Информация` opens the exercise info screen. The reference shows tabs `Информация`, `Статистика`, `История`, a large media area, favourite/edit affordances and metadata badges.
8. The edit action opens the exercise editor rather than a separate catalogue-specific form.

The product-owner screenshots are therefore stronger evidence than the flattened #58 UI that was initially inferred from strings/resources.

## Bundled catalogue extraction

`classes2.dex` contains **334 unique exercise GIF references** under `/img/gifs/180/`. `tools/extract-gym-keeper-catalog.mjs` parses these deterministically. Migrations `0007_gym_keeper_exercise_seed_01.sql` through `0013_gym_keeper_exercise_seed_07.sql` retain stable `reference_source`, exact APK-derived `reference_key` and deterministic `reference_order`.

For each bundled row the extractor reads the APK record containing the Russian display name, English/reference identity and GIF URL. The canonical user-facing name comes directly from that APK record. It is not generated by filename translation or transliteration. `reference_key` remains the immutable technical join key.

## Exact Russian-name invariant

For `reference_source = gym_keeper_apk` the Russian name stored in D1 is authoritative UI data. Runtime code must not translate or transliterate a bundled exercise. If APK extraction cannot pair a GIF record with its Russian display name, the extraction fails rather than inventing a fallback. Coach-created/user-authored exercise names remain user data and are never rewritten by this rule.

## Exercise media pipeline (#34)

Gym Keeper's production exercise library is referenced by the APK rather than embedded as 334 large GIF files inside the APK package. `classes2.dex` contains the exact production URLs on the approved host `47-1594.s.cdn13.com`, under `/img/gifs/180/`. Those APK-referenced GIFs are therefore the source of truth for the initial Mezfit media library.

The mapping is deterministic:

`exercise_definition.reference_source = gym_keeper_apk` + `reference_key` → APK `reference_media_url` → R2 object `exercise-media/gym_keeper_apk/<reference_key>`.

Migration `0015_gym_keeper_exercise_media.sql` persists the exact reference URL for every bundled exercise while preserving the stable key established by #58/#63. `tools/import-gym-keeper-media.mjs` reads the canonical 334 reference keys from the generated seed migrations, requires exactly 334 unique records, downloads each APK-referenced source, verifies the GIF signature and size, and uploads the unchanged bytes to `R2_BINDING_MEZFIT`. The deployment workflow performs this backfill when the media import inputs are introduced or changed.

The frontend never points directly at the third-party source. It uses the same-origin Worker path `/api/exercise-media/gym_keeper_apk/<reference_key>`. The Worker resolves that key through D1, serves the corresponding R2 object with immutable caching, and can recover a genuinely missing R2 object from the validated APK source URL before caching it in R2. It is not an open proxy: only known `gym_keeper_apk` keys and the approved HTTPS host/path are accepted.

GIF bytes are not transcoded, so animated demonstrations remain animated. Catalogue thumbnails, the exercise information view, and selected-client exercise lists reuse the same media identity. When no approved mapping exists, or media retrieval fails, the UI degrades to the deterministic Gym Keeper exercise icon rather than a fabricated image.

Large exercise media is intentionally kept out of the React bundle and repository. Only lightweight category UI artwork is committed to `public/`.

## Russian product invariant

Mezfit currently has a Russian-only product UI. Bundled English source names discovered in APK data must not leak to catalogue screens, search results, metadata, menus, loading/error states or other product-owned UI. Technical source keys and user-authored content are not rewritten. The canonical rule lives in `docs/product/invariants.md`.

## Mezfit domain adaptation

Gym Keeper can use direct exercise selection against the current user's diary. Mezfit coach mode manages multiple clients, so assigning an exercise cannot blindly target `today`. That separate adaptation is tracked by #61: the coach must explicitly select client and editable target day/workout, then reuse canonical program/day editor logic.

This domain adaptation does **not** justify changing category-first navigation, filter chips, row layout or context-menu semantics in the global catalogue.
