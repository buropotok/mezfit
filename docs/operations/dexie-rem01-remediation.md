## Разрешение на фактическую замену

Механизм умышленно **не публикует** файл, пока его корневой `approval_state`
не равен `approved` и каждый из шести `exercises[].approval_state` не равен
`approved`. Актуальные значения статусов проверяются в JSON в `main`. Утверждение редакций должно происходить
в отдельном проверяемом data-only изменении этого JSON; статус `applied` нельзя
выставлять до подтверждённой публикации. Поле
`automatic_application_permitted=false` сохраняется: публикация возможна только
через защищённый ручной запуск.

## Защищённая публикация

Новая GitHub Action `REM-01 - six critical public exercise corrections` запускается
**только вручную из `main` владельцем репозитория**.

1. Выбрать `preview`. Действие использует только read-only Dexie credential,
   проверяет GitHub audit-проекции 14 JSONL по SHA-256 каждого файла и pinned provenance SHA-256 исходного v2.0 каталога, точные ожидаемые значения,
   все 1324 записи, 69 анатомических узлов и манифест. Оно выводит шесть ID
   и количество необходимых замен; `publishAllowed=false` означает запрет записи.
2. Завершить ревью спорных GIF и редакций. Отдельно утвердить все шесть записей
   предложения. Повторно выполнить `preview` и удостовериться, что
   `publishAllowed=true`.
3. Выбрать `publish`, ввести `APPLY_REM_01_SIX_APPROVED`.
   Обязательны `dexie-production`, main-only environment, human reviewer и
   отдельное approval. Если защита окружения не настроена, запускать запрещено.
4. Workflow повторяет read-only preflight, создаёт полный приватный экспорт публичных
   таблиц в приватный GitHub Actions Artifact (`rem-01-public-before-<run-id>-<attempt>`, retention 30 дней),
   и **только после подтверждённой загрузки артефакта и побайтового совпадения текущего экспорта с бэкапом** повторно сверяет состояние и изменяет
   не более шести строк `publicExerciseDefinitions`.
5. Оператор снова читает все 1324 определения, 69 таксономических записей и
   манифест; любые неразрешённые изменения запрещают активацию. Только после
   полного совпадения добавляется в манифест версия
   `remediationReleaseId=REM-01`, `remediationReleaseSha256` и новое `publishedAt`,
   затем выполняется заключительное чтение. Повторный запуск идемпотентен.

Исходный приватный R2 JSON (workflow его больше не скачивает и не изменяет), `sourceSha256`, `schemaVersion`, `tracking_type`,
ID, GIF, медиа, права, realm/owner, таблица таксономии и пользовательские данные
**не изменяются**. Новые значения становятся реальными только после отдельного
успешного запуска `publish`, не после слияния PR. Если чтение после записи
обнаружит отклонение, манифест не активируется; ситуацию исследуют по сохранённому
GitHub Actions Artifact, без автоматического отката или принудительного перезаписывания.

Не используйте `publish-public-catalogue` или `tracking-publish` для исправлений REM-01.

## Источник и срок хранения резервной копии

Для REM-01 канонический вход — `audit/visual/input/catalogue_stage_01.jsonl` … `catalogue_stage_14.jsonl` и `taxonomy.json` в checkout GitHub. `manifest.json` фиксирует SHA-256 каждого этапа и SHA исходного каталога; исходный JSON из R2 побайтно не восстанавливается, но проверяется полный состав 1324 записей и структура источника. R2 не участвует в preview, backup или publish.

Artifact содержит полный экспорт только публичных таблиц Dexie Cloud (1324 определения, 69 узлов таксономии и манифест), а не пользовательские данные. Доступ к нему определяется правами GitHub Actions репозитория; срок хранения — 30 дней, поэтому для долгосрочного восстановления требуется отдельная политика архивации. Если upload не завершился, ID/digest артефакта отсутствует или состояние Dexie изменилось относительно экспортированного бэкапа, публикация запрещена.
