# Публикация каталога и медиа «Базы 2»

Защищённый оператор публикует FitnessProgramer в трёх отдельных таблицах публичного
realm `rlm-public`. Используются исходные карточки `assets/work` и GIF
`assets/media`, закреплённые хешами Git-деревьев.

| Таблица | Содержимое |
| --- | --- |
| `publicFitnessProgramerExercises` | 1 173 карточки со стабильными ID `fitnessprogramer:<slug>`, исходными полями, списком категорий и ссылкой на GIF |
| `publicFitnessProgramerGifs` | 1 167 BlobRef с MIME, размером и SHA-256 |
| `publicFitnessProgramerCatalogues` | Манифест `fitnessprogramer:v1` с хешем выпуска и ожидаемыми количествами |

Два из 1 168 исходных GIF побайтно совпадают и используют одну ссылку на Blob.
`Dead Bug` и `Hands In Air Dead Bug` входят в каталог с `gifId: null`.
Карточки с одинаковым исходным URL объединяют список категорий. Поля карточек
берутся из источника. Сопоставление с «Базой 1» не требуется.

## Первичная публикация каталога в Dexie Cloud

1. В GitHub Actions выбрать **Publish FitnessProgramer Base 2 to Dexie Cloud**
   на `main` и запустить `preview`. Проверить план схемы и данные источника.
2. Проверить доступную квоту Blob Storage для набора порядка 309 МиБ.
3. Для публикации выбрать `apply`
   и пройти ручное подтверждение окружения `dexie-production`.
4. Проверить, что итогом стал `status: verified` с 1 173 карточками и
   1 167 различными Blob. Манифест записывается после проверки всех карточек
   и повторного чтения и сверки SHA-256 всех GIF из облака.

Workflow использует действующий ключ публикации и общую блокировку писателей.
Схему и роли он читает до и после возможного добавления таблиц. Повторный запуск
продолжает незавершённую публикацию по отсутствующим записям. Конфликт по
существующему ID останавливает запуск.

## Подключение Mini App

Локальная схема Dexie v18 добавляет три таблицы опубликованного выпуска. Mini App
показывает «Базу 2» в общем каталоге и в выборе упражнений для программ и тренировок.
Для поиска и фильтров карточки преобразуются локально: используются русские и
английские названия, исходные категории, оборудование и доступные поля о мышцах.
Тип движения заполняется для кардио. Источник не содержит общих полей типа
движения и мышечного акцента для остальных карточек.

Категории и поиск доступны после получения карточек. При старте Mini App
начинает фоновую загрузку миниатюр и GIF. Приложение читает локальные файлы
из IndexedDB, скачивает недостающие из Яндекса и при ошибке использует R2.

## Публикация медиа в Яндекс и R2

Оба бакета используют ключи вида `exercises/base2/v1/<SHA-256 GIF>.gif`
и `exercises/base2/v1/<SHA-256 GIF>.webp`. WebP содержит первый кадр GIF,
вписанный в 120 × 120 пикселей. В Cloudflare используется бакет упражнений
`mezfit`, в Яндексе — `mezfit-comm-poc-20261106`.

1. В политике существующего бакета Яндекса **добавить** в `Statement` два
   правила из примера ниже. Подставить ID сервисного аккаунта из переменной
   GitHub Actions `YC_DEPLOY_SA_ID`. Сохранить правила для `mvp-media/`,
   логов и остальных пользователей бакета.
2. В CORS бакета проверить, что для origin Mini App из `MEZFIT_APP_ORIGIN`
   разрешены GET и HEAD. Действующее правило для чата уже может это разрешать.
3. После слияния PR владелец запускает на ветке `main` workflow
   **Publish Base 2 media to Yandex and R2**. Он использует существующие
   `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN` с доступом к объектам
   R2 и краткоживущий IAM-токен федерации GitHub → Яндекс.
4. Дождаться строки `Verified 1167 GIFs and 1167 WebP previews in each bucket.`
   Оператор проверяет байты каждого объекта в обоих хранилищах, тип файла
   и доступность анонимного чтения из origin приложения в Яндексе. Повторный
   запуск принимает совпадающие файлы, конфликт содержимого завершает запуск
   ошибкой. Для существующего выпуска повторять публикацию в Dexie не требуется.

```json
[
  {
    "Sid": "MezfitBase2Read",
    "Effect": "Allow",
    "Principal": "*",
    "Action": "s3:GetObject",
    "Resource": "arn:aws:s3:::mezfit-comm-poc-20261106/exercises/base2/*",
    "Condition": { "Bool": { "aws:SecureTransport": "true" } }
  },
  {
    "Sid": "MezfitBase2Publish",
    "Effect": "Allow",
    "Principal": { "CanonicalUser": "REPLACE-WITH-YC_DEPLOY_SA_ID" },
    "Action": "s3:PutObject",
    "Resource": "arn:aws:s3:::mezfit-comm-poc-20261106/exercises/base2/*",
    "Condition": {
      "Null": { "s3:if-none-match": "false" },
      "Bool": { "aws:SecureTransport": "true" }
    }
  }
]
```
