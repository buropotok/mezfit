# COMM-09 · подписанная прямая загрузка медиа

Mini App отправляет в Yandex Cloud Function JSON с исходным Telegram
`initData`, `storageKey`, MIME и размером. Функция проверяет подпись
Telegram, числовой ID и возраст `auth_date` до 24 часов с допуском
60 секунд на расхождение часов в будущем. После истечения этого срока
нужно переоткрыть Mezfit в Telegram. По умолчанию подпись доступна любому
пользователю с действительным `initData` бота Mezfit. Для закрытого теста
можно указать Telegram ID через запятую в `MEDIA_TELEGRAM_ALLOWLIST`.
Доступ к обсуждению определяют realm и ACL Dexie.

Функция возвращает `storageKey`, `putUrl` и `expiresAt` (Unix-время
в миллисекундах). SigV4 разрешает PUT на 10 минут для одного ключа
`mvp-media/<64 hex>` в `mezfit-comm-poc-20261106`. В подпись входят
`Content-Type`, `Content-Length`, `Host` и `If-None-Match: *`.
Браузер сам выставляет длину тела исходного File. MIME и длина проверяются
как параметры. Содержимое файла и длительность видео функция не анализирует.
Срок действия подписи ограничивает её использование по времени, а условный
PUT предотвращает перезапись. При повторе запрашивается новая подпись с тем же
ключом. После 412 COMM-10 проверяет MIME и длину публичным HEAD, чтобы
восстановиться после потерянного ответа на успешный PUT.

Телефон передаёт байты напрямую в Object Storage. Cloudflare может обслуживать
фронтенд и действующие операции Dexie, а выдача подписи и передача файлов
идут в Яндекс. В Dexie синхронизируются сообщение и метаданные, включая
стабильный ключ. Постоянный HTTPS URL открывается любым его обладателем без
повторного запроса к функции. Ключ формируется из 256 случайных бит без
имени файла. Удаление сообщения не отзывает ранее известную ссылку.
Используйте несекретные тестовые файлы.

## Инвентаризация до переключения

Требуется отдельное явное согласование владельца на размещение версии
Function, публичный вызов, Lockbox/ключи, IAM и изменение бакета.
Репозиторий содержит проект конфигурации. До согласования допустима
инвентаризация из авторизованной сессии владельца.

1. В каталоге `mezfit-media` сверить ID и папку существующей
   `mezfit-media-gateway`, текущую версию и теги, права вызова,
   runtime-сервисный аккаунт, предыдущий OIDC deploy-сервисный аккаунт
   и Lockbox. Сохранить ID версии и состояние привязок для отката.
2. Сохранить ACL, Bucket Policy, CORS и настройки Public access для
   `mezfit-comm-poc-20261106`. Зафиксировать отсутствующие настройки и
   инвентаризировать ACL старых объектов и lifecycle, особенно правила для
   `mvp-media/`. Держать снимки и ключи объектов в защищённом месте.

   ```sh
   bucket=mezfit-comm-poc-20261106
   endpoint=https://storage.yandexcloud.net
   aws --endpoint-url "$endpoint" s3api get-bucket-acl --bucket "$bucket"
   aws --endpoint-url "$endpoint" s3api get-bucket-policy --bucket "$bucket"
   aws --endpoint-url "$endpoint" s3api get-bucket-cors --bucket "$bucket"
   aws --endpoint-url "$endpoint" s3api get-bucket-lifecycle-configuration --bucket "$bucket"
   ```

3. Выбрать существующий сервисный аккаунт с минимальными правами. Указать его
   ID в [фрагменте Policy](../../../infra/yandex-media-mvp/policy.fragment.json).
   Выдать право условного `s3:PutObject` на `mvp-media/*` через Policy.
   Сверить наследуемые IAM и ACL, чтобы у подписанта отсутствовали лишние
   права на запись вне префикса, удаление и администрирование бакета.
   Runtime получает право чтения только используемого Lockbox payload.
   Если подтверждённого подходящего аккаунта или статического ключа нет,
   согласовать их отдельно.

## Развёртывание после согласования

1. Собрать ZIP из содержимого `infra/yandex-media-mvp/function/`, с
   `index.js` и `package.json` в корне. В **существующей** функции создать
   версию Node.js 22, entrypoint `index.handler`, память 128 МБ,
   таймаут 10 секунд. Указать подтверждённый runtime-аккаунт. Привязать
   следующие переменные через существующий Lockbox (или его согласованную версию).

   | Переменная | Значение |
   | --- | --- |
   | `TELEGRAM_BOT_TOKEN` | Токен бота Mezfit |
   | `MEDIA_S3_ACCESS_KEY_ID` | ID статического ключа аккаунта-подписанта |
   | `MEDIA_S3_SECRET_ACCESS_KEY` | Секрет этого статического ключа |
   | `MEDIA_ORIGINS` | Точный HTTPS origin действующего Mini App. Поддерживается список через запятую |
   | `MEDIA_TELEGRAM_ALLOWLIST` | Необязательный список Telegram ID тестеров |

   Последние две переменные задаются в конфигурации Function. Пара ключей,
   бот-токен и IAM-токены остаются на сервере. SigV4 URL по протоколу содержит
   идентификатор ключа в `X-Amz-Credential` и ограниченную подпись. ID сам
   по себе не позволяет подписывать запросы. Отключить логирование тел
   запросов и ответов. Для вызова из WebView разрешить публичный вызов только
   этой Function. CORS отвечает на POST/OPTIONS для разрешённых origin.
2. В [правиле CORS бакета](../../../infra/yandex-media-mvp/cors.rule.json)
   подставить реальный `location.origin` и сверить порядок правил с
   сохранённой конфигурацией. Нужны PUT/GET/HEAD и заголовки Content-Type,
   If-None-Match, Range. Длина тела выставляется браузером, поэтому
   `Content-Length` не нужно отправлять из JavaScript или разрешать как
   заголовок preflight. Проверить через клиент, что iOS и Android посылают
   подписанный Content-Length для File. Origin определяет CORS независимо
   от хостинга фронтенда. Будущий Capacitor может иметь другой origin,
   а standalone-клиенту понадобится отдельный вход, поскольку в нём нет
   Telegram `initData`.
3. Установить узкий грант подписанта. Из разрешённого Mini App проверить
   получение ссылки и записать тестовый объект подписанным PUT.
   Пока действует старый публичный ACL, это предварительная проверка.
4. Сразу после предварительной проверки убрать публичные READ и WRITE
   из ACL бакета, сохранив права владельца и необходимые частные гранты.
   Удалить и старое публичное разрешение условного PUT из Bucket Policy.
   Отключить общие public read/list/config и проверить отсутствие широких
   публичных грантов в Policy и ACL существующих объектов. Объединить
   адресный HTTPS GetObject на `mvp-media/*` из фрагмента с согласованными
   существующими правилами. Широкий публичный переключатель чтения открывает
   весь бакет и для этой схемы не подходит.
5. Выполнить облачные проверки ниже **после** отзыва старых грантов. При
   нарушении условного PUT или изоляции публичного GET от листинга остановить
   переключение и зафиксировать точный ответ сервиса. Сверить доступ владельца
   через Yandex Console.
6. Перед выкладкой фронтенда задать GitHub Actions variable
   `VITE_YANDEX_MEDIA_FUNCTION_URL` как `https://functions.yandexcloud.net/<id>`.
   Скоординировать шаги 4–6: старый фронтенд не сможет загружать после отзыва
   публичного WRITE, пока не опубликована сборка с новой конфигурацией.
   Действующий deploy фронтенда подставляет URL при сборке. Изменение этого
   кода само по себе не развёртывает функцию и не меняет настройки Яндекса.

## Ручная публикация кода через GitHub Actions

После настройки существующей версии функции владелец репозитория может
открыть **Actions → Deploy Yandex media gateway → Run workflow**, выбрать
`main` и ввести `DEPLOY_YANDEX_MEDIA`. Для предварительной проверки включить
`check_only`. Этот режим проверяет обмен OIDC, право чтения функции и версии,
совпадение аккаунта выполнения и наличие конфигурации подписанта. Право
создать версию и фактическое чтение Lockbox в рантайме он не подтверждает.

| Repository Variable | Назначение |
| --- | --- |
| `YC_DEPLOY_SA_ID` | Существующий аккаунт `mezfit-github-deploy` для обмена OIDC |
| `YC_RUNTIME_SA_ID` | Аккаунт выполнения, который уже закреплён за текущей версией |
| `YC_FUNCTION_ID` | ID существующей функции `mezfit-media-gateway` |
| `YC_FOLDER_ID` | ID её каталога |

Сохранить OIDC subject `repo:buropotok/mezfit:ref:refs/heads/main`. GitHub
Environment изменил бы subject и нарушил действующую федерацию. Для
публикации через REST сверить действующие гранты deploy-аккаунта.
`functions.editor` на существующей функции даёт чтение конфигурации и
создание версии. `iam.serviceAccounts.user` нужен на аккаунте выполнения,
который прикрепляется к версии. Runtime-аккаунту нужен
`lockbox.payloadViewer` на используемом секрете и, при шифровании собственным
ключом, `kms.keys.encrypterDecrypter` на этом ключе. Проверьте эти гранты в
консоли. Workflow не меняет IAM и не читает payload из Lockbox.

При публикации workflow берёт `$latest` проверенной функции, переносит
переменные и привязки Lockbox вместе с остальными документированными
настройками версии, публикует код `infra/yandex-media-mvp/function/` и
сверяет результат с запросом. Старые пользовательские теги остаются
на своих версиях. Если в `$latest` отсутствуют `MEDIA_ORIGINS` или
привязки трёх обязательных переменных подписанта из таблицы выше,
workflow остановится до публикации. Первоначальную настройку этих
параметров нужно выполнить отдельно по согласованному плану.

В логах есть ID исходной и опубликованной версий и ID операции. При ошибке
или таймауте сначала проверьте результат операции и `$latest` в консоли.
Публикация не меняет доступ к функции, ACL/CORS бакета или деплой Cloudflare.
См. [права Functions](https://yandex.cloud/en/docs/functions/security/),
[настройку Lockbox](https://yandex.cloud/en/docs/lockbox/operations/serverless/functions)
и [CreateVersion](https://yandex.cloud/en/docs/functions/functions/api-ref/Function/createVersion).

## Проверки

**Автоматические в GitHub Actions.** Проверить контракт подписанта, отказ
без Telegram-аутентификации, политику как артефакт, прямую отправку оригинала,
истечение и повтор, обработку сетевых ошибок и сохранение COMM-10. Моки не
подтверждают разрешения действующего бакета.

**На действующем бакете после согласования.** Для одноразовых тестовых
объектов проверить 401 на отсутствующий, изменённый и просроченный `initData`.
С действительной подписью PUT должен пройти. Изменение метода, ключа,
подписанных заголовков или размера, а также просроченная подпись должны
получить отказ. Повтор подписанного условного PUT по занятому ключу должен
вернуть 412 и оставить прежние байты. Анонимный PUT должен получить отказ
и с `If-None-Match: *`, и без него. Проверить отказ ListObjectsV2,
анонимных DELETE и изменения ACL, а также GET известного объекта вне
префикса. Без авторизации проверить GET и HEAD известного ключа
`mvp-media/`, GET с `Range: bytes=0-63` должен вернуть 206 с Content-Range.
Не сохранять подписанный URL или исходный `initData` в отчёте.

**На Android и iOS без VPN.** В уже открытом Mini App проверить отдельно
доступность Function (POST и CORS), затем прямой PUT, GET и перемотку.
Доступность бакета сама по себе ничего не говорит о доступности Function.
На двух аккаунтах проверить фото, видео до 3 минут, вложение без текста,
появление у получателя после синхронизации Dexie, отмену, обрыв и возврат
в приложение. Повтор должен сохранить ключ и не создать второго сообщения.
В диагностике доступен подписанный PUT. Анонимные отрицательные проверки
выполняются отдельно на тестовых ключах по согласованию с владельцем.

## Откат и стоимость

При проблемах с релизом восстановить последнюю проверенную защищённую версию
функции и переменную сборки или приостановить отправку медиа, сохранив чтение
готовых объектов. Если такой версии ещё нет, снять публичный вызов Function
и оставить загрузку недоступной до исправления. Снимки CORS, Policy и ACL
использовать для восстановления необходимых частных правил и доступа
владельца. Публичный WRITE не возвращать. Если требуется немедленно отозвать
уже выданные URL, отключить статический ключ по отдельному согласованию.
Простое отключение Function не отзывает выданные URL.

Учитывать стоимость выполнения Function, операций хранения, Lockbox и
исходящего трафика, включая публичные загрузки файлов получателями.
Allowlist ограничивает число пользователей, которым выдаются подписи,
и не является квотой. Настроить бюджетные уведомления и мониторинг
отказов Function и S3. Прерванная отправка после успешного PUT может
оставить объект без сообщения. Удалять подтверждённо бесхозные тестовые
объекты должен оператор, поскольку готовые объекты лежат в том же префиксе.

[PutObject](https://yandex.cloud/en/docs/storage/s3/api-ref/object/upload),
[Bucket Policy](https://yandex.cloud/en/docs/storage/concepts/policy).
