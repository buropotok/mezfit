# COMM-08: единый список обсуждений

Реализация issue #643 поверх COMM-06/07. Одна сущность — один диалог внутри
пары. Нижний пункт «Обсуждения» заменяет «Программы» для обеих ролей;
«Программы» открываются через Navbar. В Coach / Клиент добавлена отдельная
вкладка, ограниченная `coachClientId` этого контакта.

`DiscussionsProvider` разделяет один role-scoped локальный observer между
нижним unread и списком. Вне экранов списка читаются только headers/read-state и
индексированные unread, без последних реплик и метаданных файлов. Область — личный realm и проверенные контакты данной
роли, для Client — все его тренеры независимо от выбранного тренера программ.
Каждый `DiscussionRepository.feed()` повторно проверяет membership существующим
контрактом. UI-фильтр не является ACL. Отозванная пара исключается, ошибка
чтения показывается с повтором; локальные записи не удаляются.

`feed()` — производная проекция headers, сообщений, read-state и метаданных
вложений. Ни новых таблиц, ни записей-копий, ни собственного sync/cursor нет.
Существующие headers одной сущности группируются по `anchorKey`; при наличии
canonical header он представляет диалог, иначе используется первый исторический
header. При открытии применяется тот же `ensureEntityThread`, что и у входов
сущности: canonical DiscussionSheet читает все исходные headers без перемещения
сообщений. Общий unread суммирует каждый исходный thread ровно один раз,
независимо от фильтра и числа уже показанных строк.

Последняя доступная реплика вычисляется из валидных не удалённых сообщений,
без приватных черновиков. `lastActivityAt` — лишь прежняя подсказка, не источник
порядка/даты. После удаления последней реплики берётся предыдущая. Пустой
диалог остаётся в секции «Без сообщений», без выдуманной даты. При равных
timestamp порядок определяется `threadId`. Секции используют локальную
календарную дату устройства: Сегодня / Вчера / дата; подписи обновляются при
resume и в течение минуты после полуночи. Диапазон включителен по локальным датам.

UI использует публичный `List divider="inset"` и `ListItem.trailingAction`,
поскольку требуется отдельное действие справа без вложенных button. Слоты
содержат аватар существующего CloudContact, имя, контекст, ellipsis preview,
время, unread и скрепку. Типографика семантическая; CSS касается только своего
контента. Геометрия/механика UIkit не меняются. Фильтр клиента использует
публичный Konsta ListInput/select; даты — существующий Mezfit DatePicker.
Первые 50 строк дополняются кнопкой «Показать ещё»; это пагинация локальной
проекции, не второй механизм загрузки или облачного курсора.

Скрепка требует валидные metadata `ready` в том же realm, валидное живое
сообщение и отсутствие `deletedAt`. В текущем контракте нет поля expiry;
retention/фактический media gateway относятся к COMM-09–13. Истёкшие/удалённые
объекты будущая retention-проекция должна исключать своим авторитетным
metadata-контрактом. Скрепка не является URL или подтверждением доступности
сервера хранения. Превью/загрузка/отправка медиа здесь не добавлены.

«К сущности» использует типизированный `readDiscussionDestination` и текущие
авторизованные repositories. Program открывает существующий details; occurrence
без исполнения — существующий read-only sheet; execution — существующий
WorkoutSessionCard с точным упражнением/подходом в развёрнутом виде. Provenance
`occurrenceId` сохраняется, PLAN ID и execution ID не смешиваются. Отсутствующий
объект/дочерняя запись не заменяется соседним. Исторический `legacy-session`
без принятого экраном execution reader остаётся недоступной целью; история
обсуждения читается, ID не переинтерпретируется как adHoc ID.

Back принадлежит NavigationShell. Открытие sheet/сущности регистрирует вложенный
контекст, закрытие возвращает к прежней ленте, её фильтрам и scroll identity.
На странице клиента сохраняется его workspace. Позднее открытие диалога после
другого перехода игнорируется. Локальные чтения работают без ожидания cloud;
pending/offline/error и медленная первичная гидратация отображаются отдельно.
Новые flags, workflows, Apply, ACL/schema, push и media runtime не добавлены.

Проверки исходников: новые тесты ленты/изоляции, legacy aggregation, edit/delete,
read-state, вложений, локальных дат, независимых действий строки, фильтров,
пагинации, Back и устаревшего открытия; тест Navbar заменяет явно упразднённый
нижний пункт и проверяет Programs в меню обеих ролей. Локальные npm/typecheck/
tests/build не запускаются по workflow проекта; GitHub CI выполняет их после PR.
Реальные Telegram iOS/Android, multi-device и no-VPN acceptance не подтверждены.
